# 云上版前端改造规范

最后更新：2026-06-16
适用项目：`E:\qianduan\director-video-ui-cloud`

这份规范用于约束云上版前端后续改造方式，避免因为赶工继续把页面、接口、权限和样式堆到一起，导致上线后难维护。

## 1. 总体原则

- 云上版前端基于当前项目继续改造，不再沿用老的内网专用页面逻辑
- 所有权限控制以云上版后端返回的“当前租户可访问路由”作为唯一准入依据
- 不允许只隐藏菜单而保留可直接访问的静态业务路由
- 不允许继续扩张“大而全”的单文件页面，后续要按业务职责拆分
- 前端接口适配以新后端仓库 `director-video-service-cloud` 为准，不再为了兼容旧接口继续叠加分支逻辑
- 所有前端改造遵循“资深前端维护规范”，优先保证结构清晰、状态边界明确、后续可拆可测

## 2. 前端代码规范

### 2.1 目录职责规范

- `views/` 只放页面级文件
- `components/` 只放复用组件或页面拆分子组件
- `api/` 统一管理接口调用
- `store/` 只放全局状态
- `utils/` 只放纯工具方法
- `type/` 统一维护类型声明

### 2.2 Vue 组件编写规范

- 优先使用 `script setup + TypeScript`
- 一个页面文件只负责页面级编排，不在页面里堆全部业务实现
- 页面内超过一个完整业务块时，必须拆子组件
- 子组件命名使用明确业务名，不使用 `Test`、`Temp`、`NewPage` 这类无语义命名
- 组件 `props`、`emit`、返回数据结构要有明确类型

### 2.3 状态管理规范

- `pinia store` 只保存真正全局共享的数据：
  - token
  - 当前用户
  - 当前租户
  - 租户列表
  - 当前菜单
  - 标签页
  - 全局主题设置
- 列表筛选、弹窗开关、表单输入、tab 状态等页面私有状态，不放全局 store

### 2.4 接口调用规范

- 页面中不直接散写大量 `request({...})`
- 所有接口优先下沉到 `src/api/`
- 一个业务域一组接口文件
- 页面层只调用 API 方法，不自己拼大量 URL
- 接口入参与出参字段名，统一按云上版后端文档对齐

### 2.5 命名规范

- 组件文件名使用 `PascalCase`
- 页面目录名与业务域保持一致
- 变量、函数、接口字段优先使用语义明确的英文命名
- 不再新增拼音缩写、无含义单字母命名、临时变量长期保留现象

### 2.6 注释规范

- 不要求所有代码写注释
- 复杂状态流转、权限逻辑、路由重建、租户切换、动态表单映射必须写注释
- 注释要解释“为什么这么做”，不是解释表面语句

### 2.7 编码与乱码修复规范

- 项目内所有源码、文档、配置文件统一使用 `UTF-8`
- 发现中文乱码、注释乱码、模板文案乱码，必须在改造过程中同步修复
- 不允许为了赶工保留明显乱码到后续阶段
- 每完成一个阶段，要至少做一次乱码巡检

巡检范围：

- `.vue`
- `.ts`
- `.md`
- `.json`
- `.env*`

巡检要求：

- 检查模板中文
- 检查注释中文
- 检查接口提示文案
- 检查页面标题、菜单标题、按钮文案

### 2.8 样式编写规范

- 页面主色、边框、阴影、圆角、背景层次统一
- 不允许每个页面单独定义一套风格
- 优先复用统一的页面容器、卡片、筛选区、弹窗、表格头部样式
- 登录页、404 页、权限管理页、业务页要共享同一套视觉语义

### 2.9 产品文案规范

- 面向剪辑、运营、内容团队的页面文案，优先使用“团队、成员、功能、工作台、内容生成、素材管理”这类业务语言
- 不直接把后端实现术语暴露给最终用户：
  - `租户` 前台优先展示为 `团队`
  - `路由` 前台优先展示为 `功能范围` 或 `工作入口`
  - `权限点` 前台优先展示为 `可执行操作`
- 后端保留原始字段和编码，前端通过统一映射方法转换展示文案
- 路由标题、角色名称、状态名称、权限动作名称，优先收口到统一映射文件维护，避免散落在各页面重复手写
- 页面标题、按钮文案、提示语要先过“用户是否看得懂”这道检查，不用开发者内部术语直接上屏

### 2.10 删除与隐藏规范

- 第一阶段不用的页面，不做“假保留”
- 不开放的页面要从动态路由源头裁掉
- 无价值旧页面、旧接口适配层、旧权限兼容逻辑，确认无用后要清理
- 不允许长期保留“以后可能用”的死代码堆积
## 3. 路由与权限规范

### 2.1 路由准入原则

- 静态路由只保留最小基础页面：
  - `Login`
  - `Redirect`
  - `401`
  - `404`
- 业务页面路由全部通过后端接口 `/api/user/get-route/` 动态生成
- 前端不得静态写死“租户业务页面可访问路由”
- 用户手动输入未开放页面路径时，必须进入 `404` 或被重定向到首页

### 2.2 租户权限原则

- 登录后必须拉取：
  - 当前用户
  - 当前租户
  - 当前租户可访问路由
- 同一账号切换租户后，必须重新拉取路由并重建动态菜单
- 不允许沿用上一个租户的菜单缓存
- 不同租户是否开放某个页面，由后端返回路由控制，不由前端写死判断
- 权限判断必须同时考虑：
  - 当前用户身份
  - 当前租户
  - 当前租户角色
  - 当前角色可访问菜单

### 2.3 路由管理页面要求

- 云上版必须新增“租户管理”和“租户路由开放管理”能力
- 该页面用于查看和维护：
  - 租户列表
  - 当前租户角色
  - 角色可访问菜单
  - 路由开关状态
- 页面放在用户/权限管理域，不再沿用老项目里散乱的 `Permission/*` 结构

建议路径：

- `src/views/User/TenantManagement.vue`
- `src/views/User/TenantRouteManagement.vue`

### 2.4 角色管理边界

- 角色管理必须纳入租户边界控制
- 不同租户下的角色相互隔离，不允许跨租户查看、编辑、授权
- 角色可访问页面范围必须受当前租户限制
- 某些角色不能使用某个页面时，前端必须同时做到：
  - 菜单不展示
  - 路由不注册或访问时拦截
  - 页面内按钮与操作项按权限禁用或隐藏

页面要求：

- 云上版第一阶段要保留并改造“角色权限管理”页面
- 超级管理员可查看所有租户下的角色
- 租户管理员仅可查看和维护自己租户下的角色
- 普通用户不应进入角色管理页面

建议路径：

- `src/views/User/RolePermissionManagement.vue`

### 2.5 管理范围规则

云上版第一阶段前端必须清晰区分两类管理身份：

- 超级管理员
  - 可以查看所有租户
  - 可以切换所有租户上下文
  - 可以维护所有租户下的角色路由
  - 可以进入租户管理页面
- 租户管理员
  - 只能查看自己所属租户
  - 只能管理自己租户下属角色的路由
  - 不能操作其他租户
  - 页面上必须隐藏或禁用超范围操作入口

前端处理要求：

- 超级管理员看到“租户选择器 + 全租户视角”
- 租户管理员只看到当前租户，不显示全租户切换能力
- 后端返回无权限时，前端要有明确提示，不允许静默失败
- 角色权限页面必须体现“角色属于哪个租户、当前能管哪些页面、不能越权修改哪些路由”

### 2.6 数据边界规则

云上版前端所有列表、详情、筛选、统计视图都必须体现数据边界，不允许只做页面权限、不做数据范围限制。

三类身份的数据边界：

- 超级管理员
  - 可查看所有租户数据
  - 可主动选择某个租户后查看该租户的完整数据
- 租户管理员
  - 只能查看当前租户的全部数据
  - 不能切换到其他租户
- 普通用户
  - 只能查看自己的数据
  - 不能查看同租户其他用户的数据

前端处理要求：

- 页面筛选栏、租户选择器、列表结果、详情页文案都要与当前身份的数据边界一致
- 超级管理员的“租户选择”是主动切换视角
- 租户管理员和普通用户不应看到超范围的数据切换入口
## 4. 页面拆分规范

- 超过一个完整业务功能集合的页面，必须拆分

  - 页面级状态组织
  - 页面级事件协调
- 列表、筛选区、弹窗、表单、详情区、上传区、预览区等都要拆成子组件

## 5. 接口层规范

### 4.1 接口收口原则

- 所有 HTTP 请求统一放到 `src/api/` 下管理
- 页面组件里不允许继续大面积直接写 `request({...})`
- 一个后端业务域对应一个前端 API 文件

建议收口方式：

- 用户与租户权限：`src/api/user/`
- 租户管理：`src/api/tenant/`
- 素材与视频生成：`src/api/material/`
- 路由权限管理：`src/api/tenant/` 或 `src/api/user/route.ts`
### 4.2 云上版接口约束

- 用户相关接口统一使用 `/api/user/*`
- 不再保留 `/api/users/*`
- 不再保留 `/api/User/*`
- 新接口字段名优先使用云上版后端文档定义
- 后端已明确改成 `camelCase` 的请求字段，前端必须同步调整
## 6. UI 统一规范

### 5.1 整体方向

- 主题定位为“内容支持工具”
- 视觉需要偏稳重、专业、现代，不做花哨运营风
- 登录页和 404 页必须重设计，不沿用现在的通用后台默认风格
- 权限相关页面和业务页面要保持同一套后台设计语言

### 5.2 后台页面统一要求

- 页面主容器统一使用：
  - 页面标题区
  - 内容卡片区
  - 操作栏
  - 表格区
  - 分页区
- 筛选栏统一样式，不允许一个页面一个风格
- 表格头、按钮尺寸、标签色系、弹窗间距要统一
- 左侧菜单的图标、分组、展开逻辑要统一，不做多套风格混搭

### 5.2 登录页要求

- 页面视觉风格要更大气
- 要体现“内容支持工具”的业务定位
- 不允许继续使用纯深色空白背景加简单表单的旧样式
- 需要有完整的：
  - 品牌标题
  - 副标题
  - 登录卡片
  - 背景氛围层
  - 租户化/内容生产相关文案提示

### 5.3 404 页面要求

- 页面视觉和登录页保持同一套设计语言
- 不能只是基础的 “404 Not Found”
- 需要明确提示：
  - 页面不存在
  - 或当前租户无访问权限
- 需要提供回首页或返回上一页入口
### 5.4 权限管理页面视觉要求

- 租户管理、角色权限管理、路由权限管理这三类页面必须风格统一
- 树结构、穿梭框、勾选区、详情卡片要统一交互模式
- 对“超级管理员”和“租户管理员”的操作范围差异，要通过页面结构明显体现

## 8. 联调与测试规范

### 7.1 测试方式

云上版前端后续采用“两层测试”：

- 第一层：我本地实际点页面做关键链路验证
- 第二层：补浏览器自动化冒烟测试

### 7.2 自动化测试策略

后续优先建设最小可用冒烟测试，覆盖：

- 登录
- 获取当前用户
- 获取当前租户
- 获取动态路由
- 未授权路由拦截
- 租户切换后菜单刷新
- 角色权限管理页打开与权限范围校验
- 租户管理员越权访问拦截
- 超级管理员跨租户切换与菜单刷新
- 超级管理员查看全租户与单租户数据边界
- 租户管理员仅查看本租户数据边界
- 普通用户仅查看本人数据边界
- 用户管理列表加载
- 素材管理主要 tab 打开
- 快速生成页面打开
- 单条视频生成页面打开

推荐方案：

- 使用浏览器自动化方式做页面冒烟
- 当前已验证可用：Codex 内置浏览器 + Playwright API，可打开 `http://localhost:3002/#/` 并读取登录页 DOM
- 后续前端联调优先采用这套 Playwright 自动化能力做登录、页面跳转、弹窗打开、按钮点击、接口状态检查
- 如果本机 Chrome 插件/Playwright 插件后续暴露独立命令入口，也按同一套用例口径执行，不另外维护一套手工测试标准
- 测试脚本统一放到前端项目独立测试目录

### 7.2.1 浏览器自动化执行约定

- 测试前确认前端 dev server 和后端服务已启动
- 先访问登录页，确认页面标题、输入框、登录按钮存在
- 使用测试账号完成登录后，再进入目标业务页面
- 每个页面至少校验：页面可打开、核心按钮可点击、核心弹窗可打开、关键接口无 401/404/500
- 对弹窗类页面，要额外检查列表卡片、图片、按钮、滚动加载是否正常
- 测试过程中的截图、日志、临时脚本统一放入测试目录，验证结束后清理不再使用的临时数据

### 7.3 测试收尾规则

- 每次本地联调后要关闭前端 dev server、后端测试服务和相关临时进程
- 不保留无意义的测试产物在项目根目录
- 测试脚本、截图、报告统一收口到测试目录

### 7.4 测试报告规范

- 第一阶段自动化测试完成后，必须输出一份中文测试报告
- 测试报告至少包含：
  - 测试时间
  - 测试环境
  - 测试范围
  - 测试账号/租户范围
  - 身份与数据边界验证结果
  - 测试结果
