# 云上版前端第一阶段实施方案

最后更新：2026-06-12
适用项目：`E:\qianduan\director-video-ui-cloud`
目标阶段：第一阶段上线版

## 1. 阶段目标

第一阶段不是把老前端所有页面迁完，而是先完成一个“可登录、可控权限、可用核心业务页面”的云上版前端。

本阶段上线目标：

- 接入云上版后端登录体系
- 接入租户态和租户动态路由
- 接入租户管理与租户路由管理
- 接入角色权限管理与角色越权拦截
- 保证未开放页面无法通过输入地址访问
- 保留并打通首批业务页面
- 重做登录页和 404 页面
- 提供租户管理页面和租户路由开放管理页面
- 为后续大页面拆分和自动化测试打下底座

## 2. 当前项目现状判断

### 2.1 当前前端优点

- 已经有动态路由基础能力
- 已经有登录态、菜单、标签页和全局请求拦截器
- 业务页面样式整体可继续沿用，不需要完全推翻

### 2.2 当前前端主要问题

- 仍混用旧接口：
  - `/api/user/*`
  - `/api/users/*`
  - `/api/User/*`
- 仍存在静态业务路由，无法彻底阻止手输地址访问
- 页面职责过重，尤其是：
  - `MaterialManagement.vue`
  - `GenerateVideo.vue`
- 有大量云上版第一阶段用不到的页面
- 登录页和 404 页风格较弱，不符合上线版要求
- 权限管理域还没有针对“超级管理员 / 租户管理员”做前端范围控制
- 项目中部分 `.vue` 文件存在历史乱码，后续改造时必须同步修复

## 3. 第一阶段执行顺序

### 第 0 步：仓库准备

- 将当前前端工作目录的远端仓库切换到：
  - `https://github.com/chuxiaoran1124/director-video-ui-cloud.git`
- 保留你已经手动删除的旧 `docker/*` 文件和压缩包处理结果，不把它们作为当前方案阻塞项
- 后续提交统一走云上版前端仓库

### 第 1 步：权限底座改造

目标：

- 登录
- 当前用户
- 当前租户
- 当前租户列表
- 动态路由
- 未授权拦截
- 管理身份范围判定
- 角色页面级权限判定

具体改造：

- 改 `src/api/layout/index.ts`
- 改 `src/store/modules/layout.ts`
- 改 `src/type/store/layout.ts`
- 改 `src/permission.ts`
- 改 `src/router/index.ts`
- 保留最小静态路由，业务路由全部改为动态挂载
- 在 `store` 中补齐：
  - `tenantList`
  - `tenantRoleCodes`
  - `isSuperAdmin`
  - `isTenantAdmin`
- 页面按钮级权限后续通过当前角色和页面授权信息统一控制

完成标准：

- 登录成功后能正确拿到：
  - `accessToken`
  - `currentTenant`
  - `tenantList`
  - 可访问路由
- 刷新页面不会丢失登录态
- 输入未开放路由无法进入页面
- 能正确识别超级管理员和租户管理员
- 角色无权访问的页面和操作能够正确拦截
### 第 2 步：租户管理与租户路由开放管理

目标：

- 提供租户级管理视角
- 提供租户角色路由维护能力
- 验证超级管理员与租户管理员操作范围不同
- 验证角色管理在不同租户下不越权

页面建议：

- `src/views/User/TenantManagement.vue`
- `src/views/User/TenantRouteManagement.vue`
- `src/views/User/RolePermissionManagement.vue`

#### 2.1 租户管理页

页面内容建议：

- 租户列表
- 租户筛选
- 当前租户详情
- 当前租户可用角色概览

前端权限表现：

- 超级管理员：
  - 可查看所有租户
  - 可切换任意租户上下文
- 租户管理员：
  - 仅可查看自己所属租户
  - 不显示全租户切换能力
- 普通用户：
  - 不进入租户管理页
  - 不具备租户级查看能力

#### 2.2 租户路由开放管理页

目标：

- 给租户角色分配页面访问权限
- 验证不同租户路由是否确实不同

页面内容建议：

- 顶部租户信息区
- 左侧角色列表
- 中间路由树
- 右侧权限说明与保存区
- 保存按钮
- 切换角色后查看当前开放页面

联调接口：

- `GET /api/user/get-role-list/`
- `GET /api/user/get-role-route-permission-list/{roleId}/`
- `POST /api/user/update-role-route-permission/`

完成标准：

- 能查看角色路由权限
- 能修改并保存
- 不同租户或不同角色重新登录后菜单变化正确
- 超级管理员可操作所有租户角色
- 租户管理员只能操作当前租户角色

#### 2.3 角色权限管理页

目标：

- 在角色维度查看页面授权
- 明确不同租户下的角色隔离关系
- 验证角色不能访问未授权页面

页面内容建议：

- 顶部租户范围说明
- 左侧角色列表
- 中间菜单/页面权限树
- 右侧操作权限说明
- 保存与重置动作

完成标准：

- 超级管理员可按租户查看角色权限
- 租户管理员仅能维护本租户角色
- 普通用户无法进入角色权限页
- 某角色禁用的页面，重新登录后不可见不可进
### 第 3 步：第一批页面裁剪与权限域菜单重建

目标：

- 先把不用的页面从第一阶段可见范围移除
- 降低前端联调面
- 将权限管理域菜单结构统一

操作方式：

- 从菜单源头上不返回这些页面
- 从静态路由里彻底移除不需要的业务页
- 对未迁完成的页面先不开放入口
- 权限管理域统一重组为：
  - 菜单管理
  - 角色权限管理
  - 用户管理
  - 租户管理
  - 租户路由管理

第一阶段保留页面：

- 工作台
- 登录
- 404
- 菜单管理
- 角色权限管理
- 用户管理
- 租户管理
- 租户路由开放管理
- 素材管理
- 快速生成
- 单条视频生成

第一阶段数据边界原则：

- 超级管理员默认可看全局数据，并可切换到单租户视角
- 租户管理员只看本租户数据
- 普通用户只看本人数据

### 第 4 步：登录页和 404 页重设计

目标：

- 视觉上达到可上线状态
- 贴合“内容支持工具”主题
- 和后台权限管理页保持统一的设计语言

登录页设计方向：

- 更大的品牌标题和副标题
- 内容生产/素材生成相关视觉文案
- 更强的页面层次
- 更稳定的商务型视觉

404 页设计方向：

- 明确区分：
  - 页面不存在
  - 无访问权限
- 给出返回首页和返回上一页动作
- 保持与登录页同一套视觉语言

### 第 5 步：乱码修复与编码巡检

目标：

- 修复历史快速开发遗留的中文乱码
- 避免后续继续在乱码文件上叠加开发

执行范围：

- 第一阶段涉及到的 `.vue`、`.ts`、`.md`、`.json`
- 优先覆盖：
  - 登录页
  - 404 页
  - 权限管理相关页面
  - `MaterialManagement.vue`
  - `GenerateVideo.vue`

完成标准：

- 第一阶段改造涉及文件中不再存在明显中文乱码
- 形成一次乱码巡检结论

### 第 6 步：核心业务页面联调

联调优先级：

1. 用户管理
2. 租户管理
3. 租户路由管理
4. 角色权限管理
5. 快速生成
6. 素材管理
7. 单条视频生成

原因：

- 这是第一阶段最需要上线的路径
- 后端这几块已经有较明确的文档和接口基础
## 4. 权限域页面建议结构

建议第一阶段左侧权限域菜单组织为：

- 首页
- 权限管理
  - 菜单管理
  - 角色权限管理
  - 用户管理
  - 租户管理
  - 租户路由管理

说明：

- 如果某类页面第一阶段后端能力还没完全就绪，可以先保留入口但限制只有超级管理员可见
- 对租户管理员不可见或不可操作的菜单，要在前端菜单和页面内双重限制
- 角色权限管理页用于角色维度授权
- 租户路由管理页用于租户视角下的角色路由治理
## 5. 页面拆分落地计划

### 4.1 素材管理拆分

现状：

- 一个页面混了多个 tab 业务
- 后续继续在一个文件里堆会非常难改

拆分计划：

- 第一阶段先保证旧页面可联调
- 第一阶段末尾开始结构拆分
- 拆分后保留原 URL，不影响前端导航

预计拆分块：

- 声音管理
- 数字人管理
- 关系管理
- 横幅管理
- 媒体库

### 4.2 单条视频生成拆分

现状：

- 列表、创建、详情、预览都塞在一个页面里

拆分策略：

- 第一阶段先修接口和交互
- 第二阶段拆出列表区、创建表单区和详情弹层

### 4.3 用户管理拆分

用户管理页面体量相对可控，第一阶段先不强拆，只拆：

- 用户表单弹窗
- 修改密码弹窗
### 4.4 权限管理域拆分

权限管理域第一阶段建议按“一个页面一个职责”拆分：

- `MenuManagement.vue`
- `RolePermissionManagement.vue`
- `UserManagement.vue`
- `TenantManagement.vue`
- `TenantRouteManagement.vue`

其中：

- `TenantManagement.vue` 负责租户视图和租户上下文选择
- `TenantRouteManagement.vue` 负责租户下属角色的路由授权
- 两个页面共享租户信息头部组件与权限树组件
- `RolePermissionManagement.vue` 负责角色维度的页面授权和越权校验
## 6. 测试方案

## 5.1 本地人工联调

每个里程碑改完后，我会至少做一次实际页面点击验证，重点看：

- 登录
- 菜单加载
- 路由切换
- 页面权限拦截
- 主要列表页加载

## 5.2 自动化冒烟测试

因为项目紧急，不适合全部靠人工一页页点。

第一阶段建议同步建设最小浏览器自动化冒烟测试，覆盖：

- 登录成功
- 错误账号登录失败提示
- 获取动态菜单
- 访问未授权页面被拦截
- 超级管理员进入租户管理页
- 租户管理员无法进入超范围租户页面
- 角色权限管理页打开
- 某角色禁用页面后重新登录不可访问
- 超级管理员查看所有租户数据，并切换到指定租户后数据正确收敛
- 租户管理员进入列表页后仅看到本租户数据
- 普通用户进入列表页后仅看到本人数据
- 用户管理列表加载
- 租户路由管理页打开并保存
- 素材管理页面打开并切 tab
- 快速生成页面打开
- 单条视频生成页面打开

建议后续落地方式：

- 前端项目新增浏览器自动化测试目录
- 使用固定测试账号和测试租户
- 每次关键改造后跑一次冒烟
- 自动化测试完成后输出中文测试报告
- 测试报告必须单列“数据边界验证”章节

## 5.3 验收标准

第一阶段可认为达到上线前提的标准：

- 登录链路稳定
- 租户菜单正确
- 手输未授权路由无法进入
- 超级管理员和租户管理员边界正确
- 角色维度页面权限正确
- 超级管理员、租户管理员、普通用户三类身份的数据边界正确
- 核心业务页面能打开
- 用户管理功能可用
- 租户管理和租户路由管理可用
- 角色权限管理可用
- 快速生成、素材管理、单条视频生成可进入联调
- 登录页和 404 页面达到上线视觉标准
- 第一阶段自动化测试报告已产出
