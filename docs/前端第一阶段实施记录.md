## 1. 本轮完成内容

### 1.1 权限与路由底座

- 保留最小静态路由，只保留登录、重定向、401、404
- 登录后由后端返回动态菜单和页面范围，前端按当前身份动态挂载
- 根路径不再写死跳首页，而是自动落到当前账号第一个可访问页面
- 团队切换后会重新拉取菜单和可见范围，并刷新当前上下文
- 未开放页面不能通过手输地址直接进入，统一拦截到 404

### 1.2 页面与产品文案包装

- 重做登录页与 404 页面文案，使其更贴合“内容支持工具”的产品定位
- 权限域页面统一去掉直白的后台术语：
  - `租户` 前台展示为 `团队`
  - `路由` 前台展示为 `功能范围` 或 `功能导航`
  - `权限点` 前台展示为 `可执行操作`
- 新增统一文案映射文件：
  - `src/utils/productLabels.ts`
- 统一收口以下展示映射：
  - 功能标题
  - 角色名称
  - 操作名称
  - 状态名称
  - 接入方式
  - 存储方式

### 1.3 第一阶段页面联调

- 已打通并联调以下页面：
  - 登录页
  - 功能导航
  - 账号能力配置
  - 成员管理
  - 团队管理
  - 团队功能范围
- 权限切换、团队切换、成员创建、越权拦截均已接入云上后端

### 1.4 本轮补充修正

- 修正成员创建默认身份问题：
  - 原逻辑会默认取角色列表第一个角色
  - 当前后端角色顺序里第一个角色是 `tenant_admin`
  - 这会导致新建成员存在被默认创建成管理员的风险
- 现已调整为：
  - 优先默认选中 `tenant_user`
  - 打开新建弹窗时重置表单状态
  - 创建成功后清空上一次输入，避免角色和表单脏数据串用

### 1.5 本轮界面与权限链路增强

- 用户系统相关页面已统一成同一套工作台风格：
  - 成员管理
  - 团队管理
  - 团队开放策略
  - 功能导航
  - 账号能力配置
- 这一轮新增了更完整的权限运营交互：
  - 功能入口新增、编辑、删除
  - 自定义身份新增、编辑、删除
  - 自定义身份功能范围配置
  - 普通成员升级为自定义身份
  - 普通成员升级为团队管理员
- 前端动态路由补了“孤立子页面兜底”：
  - 当后端只返回单个子页面，例如只开放 `menu-management`
  - 前端会自动把它挂回对应的业务分组下
  - 避免出现“后端有权限，但前端路由装不出来”的问题
- 功能导航页增加了只读降级：
  - 平台管理员仍走完整管理接口
  - 只读身份不再请求需要管理权限的动作字典和全量目录接口
  - 改为直接读取当前登录态已拿到的菜单范围
- 账号能力配置页补了角色切换保护：
  - 切换身份时会先清空上一个身份的勾选状态
  - 新身份权限加载完成前，保存按钮不可点击
  - 避免旧身份权限残留到新身份
