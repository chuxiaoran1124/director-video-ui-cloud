# Git 版本治理与发布配对规范

## 分支职责

- `main`：当前生产真值，只接收已经通过预发布验收的版本。
- `staging`：下一版候选集成分支。
- `feature/*`、`fix/*`：从最新 `staging` 创建并回合并到 `staging`。
- `hotfix/*`：从当前生产标签创建，完成后同时回合并 `main` 与 `staging`。
- `archive/*`：只保存历史现场，不用于构建和发布。

禁止从脏工作区、服务器临时目录或手工覆盖后的目录打包；禁止无备份强推。发布包只能从干净提交或不可移动的生产标签构建。

## 前后端发布配对

每次前端发布必须记录：前端提交和标签、构建包 SHA256、配套后端提交和标签、接口兼容结论、配置变化、回滚包及预发布报告。即使只发布前端，也必须写明后端兼容基线。

发布前执行：

```powershell
git status --short
git diff --check
npm run build
git rev-parse HEAD
git tag --points-at HEAD
```

## 回滚规则

1. 优先按发布配对整体回滚；单独回滚前端前必须确认接口兼容。
2. 只使用已记录 SHA256 的构建包或从生产标签重新构建的产物。
3. 回滚后执行登录、刷新、路由权限、下载、Network 异常循环和缓存版本检查。
4. 热修复必须回合并 `staging`，不得让正常发布重新引入故障。
5. 生产实际版本必须及时同步到 `main` 并创建新的不可移动生产标签。
