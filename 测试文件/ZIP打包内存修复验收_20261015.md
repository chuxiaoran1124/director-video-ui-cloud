# ZIP 打包内存修复与验收

## 本轮结论

C 盘释放至约 14.34 GiB 后，线上同浏览器同条视频的小 ZIP 成功。随后整批出现用户截图明确的 `Array buffer allocation failed`，不能再把整批失败解释为仅磁盘不足。

旧 `downloadVideoZip` 使用 JSZip `generateAsync({type:'blob'})`；JSZip 输出会收集块并分配整个输出大小的 Uint8Array。反馈批次媒体约 2.18 GB，原视频缓冲、输出块、最终连续缓冲可同时存在。截图与该实现确认了大包内存分配故障方向，但先前 `Failed to fetch` 的具体浏览器错误分类仍未取得，不能说本轮修复已经解释所有历史网络失败。

本轮未更新生产、未操作客户通道/任务/队列、未再下载客户完整批次。

## 修复

- 共用视频 ZIP 入口改用固定版本 `@zip.js/zip.js@2.23.0`，STORE、不并行压缩、不缓存整批输入。
- 支持 `showSaveFilePicker` 时，在用户点击时选择保存路径，逐个视频以小块写一个 ZIP，close 成功后才报告已保存。单条输入仍须先完整获取以保证失败重试不会把半条文件写进 ZIP，因此内存与当前单条视频有关，而不是整个批次。
- 不支持原生写文件时，按 256 MiB 媒体字节预算生成独立可解压 ZIP；超出单条预算的文件明确失败并建议单独直连下载。按 Content-Length 或实际读取字节提前停止超限读取。分包模式只能确认发起浏览器保存，不能确认用户已落盘，需允许多个下载。
- 不新增应用服务器下载代理，训练上传链路不变。共享入口覆盖数字人列表批量下载、批量计划详情全部下载和勾选下载；行内单条直连不变。
- 请求超时改为 180 秒无字节进展才中止，而不是 180 秒总时长；仍保留最多三次整文件尝试，不宣称已有 Range 断点续传。
- 404 等永久失败不重试，部分失败仍保存成功视频；重名条目不覆盖。
- 磁盘写入失败停止操作，abort 临时写入，不标成功；取消保存路径不请求视频。全部失败不再显示绿色“下载已开始”。

## 验证

1. 定向自动测试：17 项，包括原生流写入、close 后成功回调、磁盘写失败、取消、全失败、部分成功、同名、分包无遗漏、超限中止、持续进展重置计时器及网络重试。
2. Node 模拟 50 条、媒体 2,182,365,650 字节：输出保持小块写入，不申请整包 ArrayBuffer；不是下载真实客户视频。
3. 本地隔离浏览器测试：真实 OPFS FileSystemWritableFileStream 写磁盘。
   - 2 条：ZIP 2,097,446 字节，两个条目和首尾 CRC 校验通过。
   - 50 条：ZIP 2,182,372,554 字节，50 个条目长度正确，首尾解压及 CRC 校验通过，58.8 秒；未复现大缓冲区分配失败。
   - 临时文件由测试页清理，C 盘可用回到约 13.86 GiB。
4. cloud 构建通过；独立 writer TypeScript 检查和 git diff --check 通过。

运行测试：

```powershell
node node_modules/jest/bin/jest.js --config '测试文件/zip-test.jest.config.cjs' --runInBand
npm run build:cloud
```

## 边界与发布门禁

浏览器实测使用合成数据验证写盘与大 ZIP；不是生产站点新代码的真实 TOS 50 条端到端验收。真实保存选择器的用户操作、TOS 慢网/断网、不同浏览器的多文件权限及完整业务页面需候选测试环境进一步验收，不能将本地结果等同于生产已修复。

前端工作树有其他任务的内网迁移改动，生成的完整 dist 不能直接发生产。后续发布必须隔离本轮补丁、从正式生产前端基线准备独立候选，按正常运维门禁验证，不把其他迁移改动一并发布。生产保持不变。

维护依赖时曾出现无锁安装拉取新版 Element Plus 导致旧 Vite 解析失败；已用原锁文件加新增 ZIP 依赖，执行 npm ci 恢复 Element Plus 2.0.2/Vite 2.8.4 并重新构建成功，没有修改业务代码适配未经批准的依赖升级。既有依赖审计问题不在本轮静默自动修复。
